## Features

- **Every session in one sidebar**, including ones you started in a terminal. **Group by** *Status* (*Working now*, *Needs your review*, *Today* and older) or *Project*; click a group's heading to collapse it. Search it (`/`; `in:name` keeps one workspace's sessions, e.g. `in:api login`), filter by *All*, *Active*, *In panel* or *Archived*, archive and restore sessions, and open one in a new tab (middle-click or right-click). Rows show the session's status first, then worktree, overlap and model; a bold title means news since you last looked at it.
  - **Pin** sessions (pin button on a row) to keep them in a *Pinned* group above *Working now*, or first within their project when grouped by project. Pins persist across restarts; archiving a pinned session unpins it.
  - **Workspaces** (grouped by project): each heading shows the workspace's colour, live counts (working, waiting for you, new) and stays on top while you scroll its sessions. *Needs you* above them gathers every session waiting for you in any workspace. Hover a heading for **◎** (show only this workspace; ✕ on the chip beside *Group by* shows all again), **+** (new session there) and **⋯**: rename, colour, refresh the Git branch, open a terminal, copy the path, or hide the workspace. A hidden workspace's sessions move under *Archived*, where its **⋯** shows it again. Branches shown for workspaces follow what is checked out, refreshed every 15 seconds.
  - **Alt+J / Alt+K** jump to the next / previous session that needs you, across workspaces. **Ctrl+K** (⌘K) opens a quick switcher: type part of a session title, folder, prompt or model, or a workspace name to start a session there.
  - Drag the sidebar's right edge to resize it (double-click resets); the sun/moon button in its footer switches between the system theme, light and dark. Both are saved in this browser.
- **New session screen** (**Alt+N**): pick one of your workspaces (cards with branch, last use and what waits for you), another recent folder, paste a path or browse subfolders with a filter, then type the first prompt. Each folder remembers the worktree, launch options and model you last started it with (in this browser). *Pick up where you left off* lists your latest sessions. Sessions from OMP history can be added to the panel without sending a message.
- **Continuous work timers:** the sidebar shows **Running** elapsed time, then the frozen **Last run** duration, using hours, minutes and seconds for long runs (e.g. `1h 5m 19s`). Steering, queued continuations, question prompts, retries and background waits stay in the same interval; hover for exact start/end times.
- **Readable conversations:** Markdown, tables and code blocks with copy. Tool calls and thinking fold into one activity summary.
- **GitHub-style diffs** with word-level highlights, in unified or split view; **± N files changed** in the top bar reviews every file a session touched.
  - **Edits / Working tree / Commits:** *Edits* lists what the agent changed with its edit and write tools; *Working tree* shows the real `git diff` of the session's folder against the commit it started from (or `HEAD`), including untracked files, so shell commands, formatters and your own edits show up too; *Commits* shows the folder's git state (branch, upstream with ahead/behind, uncommitted count) and its latest 50 commits (hash, subject, author, date; *this session* marks ones made since the session started). Click a commit to see its diff (merges against their first parent). The folder is the session's worktree when it is isolated. Also opens from *⋯ › Branch & recent commits*, even before the session has edited anything; the choice of tab is remembered.
  - **Viewed** (checkbox per file) folds a file you've reviewed until its diff changes again. Kept in this browser.
  - **Review comments:** click a line number to comment on it, then **Request changes** sends every comment to the session as one message, one `path:line: note` per line (removed lines say so). It goes as a steer while OMP is working, as a new prompt otherwise.
- **Open in editor:** file names in diffs, tool calls and the same-file warning open the file at the changed line, on the computer running the companion. *Settings › Notifications & editor* picks VS Code, VS Code Insiders, Cursor, Windsurf or *Show in folder*; *Automatic* uses the first editor it finds installed.
- **Live plan and activity panel** for todos, subagents with expandable live reasoning, background jobs and advisor transcripts; **Watch →** (subagents) and **Open transcript →** (advisors) open the full transcript. A running subagent has **Steer** (send it a message at its next step) and **Stop**; the parent session keeps running.
- **Notifications:** when a session finishes, fails or asks a question while you're looking elsewhere, the tab title counts it (`(2) OMP Control Room`) until you open it, and the browser shows a notification once you allow them (the first time, a toast offers it; also *Settings › Notifications & editor*). The desktop app shows native Windows notifications instead while its window isn't focused, and its taskbar title carries the count.
- **Side questions:** `/btw <question>` (or *⋯ › Ask a side question*) asks about the session without interrupting it or adding to its conversation. The answer streams into its own panel above the composer; ask follow-ups on the same topic, cancel, or reopen earlier ones from *History*. Uses OMP's own `/btw`.
- **Drafts follow you:** the unsent text in each session's composer is saved to the companion, so it survives reloads and shows up on your phone or another browser. Text you've changed on this device and not yet synced is kept and saved over the other device's version, never replaced by it.
- **Same-file warning:** when two active sessions in the same folder (no worktree) edit the same file, both show a banner naming the other session and the files, and the sidebar marks them *⚠ overlap*.
- **Native plan mode:** enable read-only planning before your first prompt (**Alt+Shift+P**), review the proposed Markdown plan, request refinement, or approve implementation with the current, fresh or compacted context. Requires an OMP SDK that ships the plan-mode host (see [Native plan mode](#native-plan-mode)).
- **Native goal mode:** `/goal` opens an objective prompt or the current goal's controls; start autonomous work, replace an objective, pause/resume, set a token budget, or confirm dropping it. Works with released OMP SDKs (see [Native goal mode](#native-goal-mode)).
- **Smart composer:** send, steer a running turn (edit or cancel a steer until OMP reads it), queue follow-ups, attach images (button, paste or drag and drop), switch model or reasoning level from a searchable picker with favourites (Ctrl+P cycles configured default/smol/slow roles), toggle fast mode (⚡ chip, shown only for models with a priority service tier: Anthropic, OpenAI/Codex, Google, and their OpenRouter variants) in new and live sessions, use the ⚑ advisor menu to turn the advisor on or off (also before continuing a session from OMP history, applied before the first message), change its model, open its transcript, and filter its output in the chat (hide all while it keeps running, show reviews, important notes only), complete `/commands` in both new and live sessions (find skills by name, e.g. `/front` completes to `/skill:frontend-design`), complete the current word with Tab from OMP's local word predictor (n-gram or the tiny SmolLM2 model), rewrite the draft with **✨ Enhance** (below), and run `!command` in the session's shell.
- **Enhance prompt:** **✨** (or **Ctrl+Shift+E**) in every composer (live sessions, New session, and continuing a session from OMP history) rewrites your draft into a concrete prompt. Each click is one read-only `omp -p` run limited to twelve read/grep/glob lookups inside the session's folder; it uses the conversation tail and attached images to name real files and symbols. The draft is replaced in place, with **Undo** in the toast or Ctrl+Z; nothing is sent automatically, and **✕** cancels a run. The model is OMP's `enhance` role if set, otherwise the composer's model at the composer's reasoning level. On New session it creates a draft session, discarded if you leave without sending.
- **Provider usage:** **◔ Usage** in the top bar opens a live panel with every logged-in provider, the selected model's provider first, each under its own heading with one row per limit for every reported account: label, reset time, used percentage and a bar that turns red at 90 %. It refreshes in the background every 2 minutes while open; `/usage` posts the same providers to the chat as a text snapshot and works during a running turn without steering it or queueing another prompt.
- **Choose provider accounts:** logged in to the same provider more than once (for example two Claude subscriptions)? **⋯ › Choose provider accounts…** lists each provider's OAuth accounts; pick the one to use. Every session switches to it with OMP's own `/session pin` before its next message, so the choice covers new and running sessions, survives restarts (it's saved in `workspace.json`), and OMP no longer rotates that session to another account. Without a choice, OMP picks between the accounts itself. *Enhance prompt* runs (`omp -p`) have no session to pin and still use OMP's automatic pick. Reading the accounts from OMP takes a few seconds, so the companion reads them at startup and after each login from the panel, and refreshes them in the background each time the dialog opens: an account added with `omp login` in a terminal shows up the next time you open it.
- **Answer OMP's questions** (`ask` tool and extension prompts) directly in the browser. With OMP 18.10 or newer, an `ask` call arrives as one form: checkboxes for multi-select questions, radio buttons for single choice, an *Other* text field per question, and one **Submit**, so ticked options stay visible until you send them. Older OMP builds keep the one-click-per-option flow. Sessions with unanswered questions move to *Needs your review* until the last question is answered or cancelled, then return to their current work state. Extension notifications, status lines, widgets and sign-in links appear in the chat.
- **Auto-approve:** the **✓ Auto-approve** chip next to a session's model turns it on or off while the session runs, without restarting OMP. To have it on from the first turn, tick **Auto-approve** on the New session form (next to *Advisor*) before starting. While it's on, the companion answers OMP's tool-approval prompts (*Allow tool: …* → **Approve**, including MCP tools and eval preludes) and the computer tool's *Allow foreground computer control?* (→ **Yes**) as soon as they arrive, and each one it answers appears in the chat as *Auto-approved: …* with the full prompt. Turning it on also approves the approval prompts already waiting. `ask` questions, text and editor prompts, other choices and prompts that list provider safety checks still wait for you. It also continues a session that stopped on a provider **429 rate limit**: once OMP has given up retrying (for example because the provider's `retry-after-ms` wait is longer than OMP's `retry.maxDelayMs`), the chat shows *Rate limit reached; resuming automatically at HH:MM.*, and when the wait is over the companion resends the last message as **Retry** would. Stop, turning Auto-approve off or marking the session done cancels the wait (the chat says so); sending a message of your own replaces it. The resume time is saved, so a companion restart keeps the wait, and a time that passed while the companion was off resumes right after it starts. A last message with an image is not resent: reattach the image and send it yourself. With Auto-approve off, a 429 leaves the session in error until you press **Retry**. The setting is saved per session in `workspace.json`. Unlike the launch-time approval mode in **⚙ Options**, it doesn't change which tools OMP asks about, only who answers.
- **Session tools:** rename, browse the full **session tree**, copy the last reply, cycle OMP's model and thinking level, export as HTML, share a link, session stats, commit the folder's changes, provider login, **open a terminal in the session's folder** (`cmd` on Windows, Terminal on macOS, `x-terminal-emulator` on Linux; it opens on the computer running the companion, also when you use the panel from a phone), copy the working directory or `omp --resume` command, and **✓ Mark done**. While idle, the chat messages themselves carry the history actions: **Edit & resend** on your last message goes back to just before it and puts its text and images in the composer so you can change and resend it; **Regenerate** on the reply to it goes back the same way and sends that prompt again unchanged; **Branch from here** on any earlier message of yours continues from just before it, with that message back in the composer. The session menu keeps **Edit last message**, **Regenerate last reply** and **Branch from an earlier message** for the cases the chat can't show: a last message OMP didn't record as a prompt (a steer, or a command such as `/usage`), a turn that failed before replying, or messages older than the chat keeps. The session tree also has **Branch** on any of your messages, including ones on abandoned paths. The buttons need OMP's ID for each message: messages typed in the panel get it a few seconds after OMP finishes the turn, once it has stored them. Messages recorded without one (sent before this companion version, for example) get it the first time the session is idle after a companion start: the chat is then rebuilt from OMP's own record of the conversation (its active path), keeping the companion's own notes. The menu also hands off to a fresh context, compacts with optional instructions, starts a fresh OMP session (`/new`), switches the entry to another saved session, or removes it from the panel. OMP's host API can only go back in time with its `branch` call, so edit, regenerate and branch all continue in a **new OMP session file** holding the conversation up to that point; the old file stays in OMP history unchanged with the replies you went back from. OMP's in-place `/tree` move exists only in its terminal UI. Per-session toggles cover fast mode, auto-compaction, auto-retry and steer/follow-up delivery (*Deliver all steers at once*, *Send all queued follow-ups together*, *Hold steers until the turn ends*).
- **Restart companion:** *⋯ › Restart companion…* in a session's top bar stops the companion and starts it again on the same port; the PC keeps running. After you confirm, unsent composer text is saved, running sessions are paused and saved as on quit, and once the new companion answers the panel reloads itself (same connection token, no new browser tab), so companion and dashboard changes made since the last start are live; continue a session by sending it a message. Other open panels keep their page until you reload them. A restart skips the `omp update` check. The item appears only when the companion runs from `start.bat`, which does the restarting; the desktop app and a plain `node companion/server.mjs` don't offer it.
- **Shut down PC:** *⋯ › Shut down PC…* in a session's top bar turns off the computer running the companion, also when you use the panel from a phone (`shutdown /s /t 0` on Windows, System Events on macOS, `systemctl poweroff` on Linux). After you confirm, running sessions are paused and saved as on quit, so you can continue them once the PC is back on. If the OS refuses (for example a Linux polkit rule), the panel shows its error and keeps working; the sessions stay paused. *⋯ › Shut down PC when all work is done* does the same once the work is finished: the companion waits until no session is running or queued and no compaction, handoff or shell command is in progress, then shuts down exactly as above (if nothing is working when you turn it on, it shuts down right away). Messages queued behind a running turn count as part of it; messages left queued in a stopped session only go out with your next message there, so they don't hold the shutdown and stay queued for later. While it waits, the sidebar and the view's top bar show it with a **Cancel** button and the number of sessions working; those sessions are the ones the sidebar's **Active** filter lists as working (a session compacting or running a shell command shows that instead of its status). Clicking the menu item again also cancels it. The option lives in the companion, so it holds when you close the panel, but not across a companion restart. If the OS refuses, the panel shows the error, the option turns itself off and the panel keeps working.
- **Stop & send:** while OMP is working, **■ Stop & send** cancels the current turn and sends your message in its place. Plain Enter still steers; Ctrl+Enter, Alt+Enter or Ctrl+Q queue it for after the turn.
- **Hotkeys:** *Settings › Hotkeys* sets the composer keys for **Queue** and **Stop & send** (comma-separated, e.g. `Ctrl+Enter, Alt+Q`; empty turns one off). A combo is Ctrl, Alt or Meta (plus optional Shift) and a letter, digit or key name such as Enter, Space, Tab, Up, Down or Esc. Letters follow your keyboard layout; when a combo types something else (Option+letter on a Mac, non-Latin layouts) the key's position counts instead. The dashboard's own shortcuts (Ctrl+P, Ctrl+K, Ctrl+Shift+E, Alt+Shift+P, Alt+↑/↓, Alt+J/K, Alt+N) can't be reused. They're saved in this browser. Some browsers keep Ctrl+Q / Cmd+Q for themselves (Firefox on Linux, macOS), so use another combo there.
- **Prompt rail:** the thin strip right of the chat has one tick per prompt you sent, placed where it sits in the conversation. Hover a tick to preview the prompt, click to jump to it; **Alt+↑ / Alt+↓** step to the previous / next prompt. The highlighted tick is the prompt you're reading.
- **Editable task plan:** click a task's status icon in the Plan panel to cycle pending → in progress → done (or *Clear task plan*). Changes go to OMP's own todo list.
- **Launch options:** **⚙ Options** in the new-session composer and *Launch options…* in a session menu set OMP's startup flags: approval mode, tool and skill allowlists, extra folders (`--add-dir`), max run time, model roles (smol/slow/plan), plan-yolo, prewalk, system-prompt overrides, and switches such as no LSP, no rules or no extensions. Changing them restarts an idle session's OMP process.
- **Live feedback:** streaming tool output, retry progress with a *Stop retrying* button, fallback-model switches, extension errors and goals.
- **Settings UI** for every `omp config` value, for plugins and for MCP servers, plus one-click `omp update`. *Settings › MCP servers* lists the servers OMP discovers (user and project `.omp/mcp.json`, a project's `mcp.json`/`.mcp.json`, and other tools' configs OMP imports), grouped by user and project, with each server's transport, command or URL (secret values hidden), env and header names, timeout and auth, and the file it comes from. Its switch turns a server off or on the way OMP's own `/mcp enable|disable` does: OMP's own files are edited in place; for another tool's file the change goes to `disabledServers`/`enabledServers` in `~/.omp/agent/mcp.json`. Changes apply to new or restarted sessions.
- **OMP stays current:** on every start, the companion and the desktop app run `omp update` before opening, which installs a newer OMP CLI release only when one exists, then install the matching release of OMP's SDK (`@oh-my-pi/pi-coding-agent`, which sessions run) under `<data dir>/omp-sdk/` when the CLI is newer than the SDK sessions use. Sessions load OMP once per start, so a newly installed SDK takes over at the next start, and older copies are removed then. Under `start.bat` (and after **Update OMP** in Settings) the companion restarts itself for that once no session is working; the desktop app picks it up at its next launch. If either step fails (offline, for example) the companion starts with what is installed. The desktop app gives both at most 45 seconds; an SDK install still running then finishes in the background and is used from the next start. An `OMP_BIN` pointing at a source checkout's `cli.ts` is skipped: update that checkout with git. Set `OMP_WEB_NO_UPDATE=1` to skip both. The one-click update in Settings installs the matching SDK too; restart the companion to run new sessions on it.
- **Tools page** (🧰 in the sidebar) for OMP's command-line tools: AI `commit` (dry run by default), `worktree`, usage `stats`, `share`, the skills registry, advanced `plugin` maintenance, `agents unpack`, background processes (`ps`), storage cleanup (`gc`, dry run unless *Apply*), `ssh` hosts, optional-feature `setup`, `tiny-models`, semantic `find` and tool `grievances`. Commands run in the background with live output and a Stop button; arguments are validated and never pass through a shell.
- **Spend page** ($ in the sidebar): dollar cost per model for today, this month and all time, plus this month day by day. Figures come from OMP's usage stats (`~/.omp/stats.db`) and are API list prices, so subscription/OAuth usage shows what it would have cost, not what you were billed. Opening the page or ↻ Reload shows what the DB already holds right away and syncs new transcripts with `omp stats` in the background (this can take minutes after heavy use); the figures update when it finishes.
- **Screen page** (🖥 in the sidebar, Windows only): see the PC's screen live from a phone, tablet or another computer and use its mouse and keyboard, on your network or over Tailscale. It is **off until you allow it on the PC itself**: the desktop app's tray item **Allow screen sharing and control**, or `OMP_WEB_SCREEN=1` for `node companion/server.mjs` / `start.bat`; the dashboard can't turn it on. It needs the same password or token as everything else. The picture streams straight from the companion to the browser over a WebSocket (JPEG patches of whatever changed, at most ~30 fps; *Auto quality* matches the viewing screen, *Sharp* sends full resolution, *Fast* saves bandwidth), with nothing going through an outside service. One device at a time: opening it on another device takes over, and the desktop app shows a Windows notification while someone is viewing. With a mouse: click, drag, wheel; keys typed while the picture has focus go to the PC. With touch, the toolbar is one row: **Trackpad**, **⌨**, **Keys**, **⛶** and **⋯**. By default the pointer goes where your finger lands: tap clicks (two quick taps double-click), long-press right-clicks (a ring fills while you hold), one finger drags (or scrolls with **↕ Scroll** on, under **⋯**). **Trackpad** turns the screen into a laptop touchpad for targets smaller than a finger: one finger moves the drawn pointer (faster the faster you swipe), tap clicks where the pointer is, two taps double-click, tap then touch-and-drag drags, long-press right-clicks, and when part of the picture is out of view it follows the pointer. In both modes a two-finger tap right-clicks, two fingers scroll, and pinch zooms; while zoomed in the default mode, two fingers pan instead of scrolling. **⌨** opens the phone keyboard and tapping it again closes it. **Keys** adds sideways-scrolling rows: sticky Ctrl/Alt/Shift/Win, Esc, Tab, arrows, Enter, ⌫, Del, Home, End, PgUp, PgDn, and shortcuts (Copy, Paste, Cut, Undo, Select all, Save, Find, Switch app = Alt+Tab, Desktop = Win+D, Close = Alt+F4, Task Manager). **⛶** goes full screen; on iPhone, which has no full screen for pages, the picture and toolbar cover the page instead. **⋯** holds the display and quality choices and *View only*, which watches without sending input. Trackpad, Keys and View only are remembered in the browser. While the phone keyboard is open, the picture and toolbar shrink to stay above it. On a phone held sideways the page makes room for the picture: the sidebar folds into **☰**, the header goes (**☰** moves into the toolbar and **Disconnect** under **⋯**), the toolbar becomes a column on the left, and the picture fills the width with no black bars beside it. A 16:9 or 16:10 PC screen is then a little taller than the phone, so a thin strip at the top and bottom is out of view: two fingers pan it into view and, once the edge is reached, scroll the PC as usual; in Trackpad mode the picture follows the pointer there. Pinch out to see the whole picture at once, and **Fill** goes back. At most about a quarter is ever cut off this way; when more would be (a 4:3 or portrait display, or with **Keys** open), thin bars stay. Limits: Windows doesn't let it see or control the lock screen, UAC prompts or windows running as administrator, Ctrl+Alt+Del can't be sent, and shortcuts the browser keeps for itself (Ctrl+W, Ctrl+T, Ctrl+N) close or open browser tabs instead.
- **Isolated git worktrees** so parallel sessions don't overwrite each other's files. **⋯ › Finish worktree** shows the branch, commits ahead/behind and uncommitted changes, then merges (or squash-merges) it into the branch checked out in the project folder, rebases it onto that branch, pushes it, or deletes the worktree and branch. In an isolated session the composer also has **Push to main** (named after the branch checked out in the project folder, e.g. *Push to master*) next to **Commit related changes**: like that button, it sends OMP a message (queued as a follow-up while OMP is working) asking it to commit the worktree's changes on its branch, merge the branch into that branch and push it to the remote, then report the result. A merge or rebase from Finish worktree that fails is undone, and Finish worktree's merge waits until both folders are clean and OMP has finished.

## Quick start

Requires **[Bun](https://bun.sh) 1.3+**, **Node.js 22+** with npm (to install the OMP SDK and run the tests), and a configured OMP (a model provider logged in; `omp` on PATH for updates, usage, enhance and the Tools page).

```sh
npm ci
node companion/server.mjs
```

`npm ci` installs OMP's SDK (`@oh-my-pi/pi-coding-agent`), which the companion runs in its own process. The browser companion has no build step: `node companion/server.mjs` hands over to Bun (`bun companion/server.mjs` does the same directly) and runs straight from this folder. Only the [desktop app](#desktop-app-windows) needs a build.

The dashboard opens in your browser, already connected. Press **Alt+N** (or click **New session**), pick a folder, type a prompt and press Enter. Keep the companion terminal open while you work.

With **Group by Project**, hover a workspace heading and click **+** to open **New session** with that folder already selected. Project groups keep a fixed order regardless of activity; drag a project heading above or below another to reorder them. The order and which groups are collapsed are saved by the companion, so every browser and device sees the same sidebar. New projects are added at the top.

Type `/` in the composer to browse commands and skills. Use ↑/↓ to select, Tab or Enter to complete a partial name, and Esc to dismiss; clicking an option also completes it. On **New session**, the catalog follows the selected folder, including its local skills and commands, without creating a saved session.

While you type in a session's composer, OMP's word predictor shows the rest of the current word in faint text. **Tab** accepts it and **Esc** dismisses it. On phones and other touch devices, which have no Tab key, typing a **space** accepts it and keeps the space; a **backspace** right after that takes it back and restores the word as you typed it, so the next space is just a space. Keep typing to ignore it. Suggestions only appear while the session's OMP process is running, and only for prose: not for slash commands, `!` shell lines or paths. The engine follows OMP's `spelling.autocomplete` setting (*Settings*). The default `auto` uses a local n-gram model built from your prompt history. For the tiny SmolLM2-135M model, download `smollm` under *Tools › Tiny local models*, then set `spelling.autocomplete` to `smollm`. `off` turns suggestions off. Changes apply to running sessions immediately. The first suggestion after a switch can take a few seconds while OMP loads the model.

Press **✨** (or **Ctrl+Shift+E**) with a draft in the composer to enhance it. The enhancer looks up at most twelve things in the code; while it runs the composer is read-only and the status line names the model in use. If you edit the draft before it finishes, the result isn't applied and the toast offers **Use enhanced prompt** instead. *Settings › Enhance* picks the model: **Composer's model** (the default; it also uses the composer's reasoning level), or a model you choose, saved with its own reasoning level as OMP's `enhance` model role (pick something fast and cheap). With a role set, the *Reasoning level* row edits the role's level; a role saved without one runs at OMP's default level, so pick one. The enhancer can read, search and list files but cannot write, run commands, save skills or memories, or use MCP servers. A lookup guard keeps it inside the folder (no `..`, absolute paths, `~`, URLs or `.env` files) and stops it after twelve lookups, and it loads nothing from the repo's agent setup: no MCP configs, `AGENTS.md`/`CLAUDE.md`, rules or hooks.

The rewrite keeps what you asked for, in your draft's language and with the names you wrote: a question or "look at it" stays a question or a check, and "fix it" or a plain bug report ("starting video is not in sync") becomes a fix. A question is made precise and pointed at the right files, but not answered for you. For a code change it also names the cases a complete change has to handle that the enhancer saw in the code (empty or boundary values, the existing error style, sibling overloads and other callers, and sibling flows that run through the same code, such as pause, seek and a late joiner for a video that starts out of sync), and ends with a short **Done when** list: the behaviour that must work and a check the agent runs itself before it finishes, such as the repo's tests (never a manual browser check). It leaves out hardening you didn't ask for and keeps any limits you set.

On **New session**, Enhance starts the session in the picked folder right away and moves your draft and images into it. Until you send its first message it is a *draft* session: going back to New session, picking another folder or opening another session removes it again, including its OMP process and, if you ticked *Isolated git worktree*, its worktree and branch. Settings, Tools and Spend don't count as leaving.

During a running turn, Enter or **Run** dispatches slash commands instead of steering their literal text. Local controls leave the current turn and unread ordinary steers intact. **Queue** / **Alt+Enter** still defers commands until the turn finishes; `/usage` is always immediate. Restart the companion and refresh the browser after updating.

Click **◔ Usage** in a session's top bar for the live panel. It reads `GET /api/usage?session=<id>` when opened and then every 2 minutes, never starting a request while one is still running, and pauses while the tab is hidden (it refreshes as soon as the tab is shown again). One `omp usage --json` call covers every provider you are logged in to; the panel lists the selected model's provider first and the others after it, each under its provider name. Each account shows its email/org/plan, then each limit's used percentage, bar (blue, red from 90 % used) and reset time, relative within 24 hours (`resets in 2h 13m`) and local weekday and time beyond that. A provider that reports no limits, an account without usage data, or a malformed report for one provider shows **Remaining quota unavailable** for that provider or account and does not hide the others. Nothing is estimated: no remaining-message counts or session-token totals. When a refresh fails the panel keeps the last good data and shows the error under it with the last successful update time. **/usage ↗** in the panel, or sending `/usage` (or `/usage show`), puts the same providers in the conversation as a text snapshot instead, with each fetch time and UTC reset timestamps. Limits are labeled as reported, because a quota can be shared by several models. Both views use the configured OMP runtime's `usage --json` command and the same parser.

## Desktop app (Windows)

The same dashboard in its own window, with the companion running inside the app: no console window, no browser tab. The app runs the same `companion/` code as `node companion/server.mjs`, through its bundled Bun and `desktop/host.mjs`, with OMP's SDK from its bundled `node_modules/` or the newer release installed to match the `omp` CLI (see *OMP stays current* above). Like the plain companion, it listens on `127.0.0.1` with a token. The installed app needs only a configured OMP (and the `omp` CLI for updates, usage, enhance and the Tools page).

The desktop app builds on Windows only. On other systems the build stops and tells you to run `node companion/server.mjs` instead.

### Build prerequisites

- **Bun 1.3+.** The build copies the Bun that runs it into the app, so the version that builds is the version that ships. Install it from [bun.sh](https://bun.sh). After upgrading Bun, delete `src-tauri/binaries/` to bundle the new version.
- **Node.js 22+** with npm, which runs the build scripts and installs the npm dependencies (OMP's SDK and the Tauri CLI).
- **Rust**, installed with rustup. Open a new terminal afterwards so `cargo` is on PATH.
- **MSVC C++ build tools.** Rust needs their linker.

Install Rust and the build tools once:

```sh
winget install --id Rustlang.Rustup -e
winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

You don't install the Tauri CLI yourself. When `node_modules/@tauri-apps/cli` is missing, the build runs `npm ci` first. It installs exactly the committed lockfile and leaves it unchanged.

### Run and build

```sh
npm run desktop
```

**`npm run desktop`** runs `tauri dev`: it starts the app from this checkout, for development.

```sh
npm run build
```

**`npm run build`** runs `tauri build` and produces the installer. **`npm run dist`** builds the release variant (`--config src-tauri/tauri.release.conf.json`), which also writes the installer's update package and its signature; it needs the updater signing key (see [Releases](#releases)).

All three commands first run `scripts/check-build.mjs`. It runs `npm ci` when the npm dependencies are missing; if Bun, Rust or the MSVC build tools are missing, it stops before cargo starts and prints the install command for each.

### Install

The build writes an NSIS installer to `src-tauri/target/release/bundle/nsis/OMP Control Room_<version>_x64-setup.exe`. Run it. It installs for your user only (no admin rights) and adds **OMP Control Room** to the Start menu. The installer carries Bun plus `companion/`, `node_modules/` (OMP's SDK), `local-dist/` and the `desktop/` host scripts, so the PC needs no separate Bun or Node.js install. The installer is unsigned, so Windows SmartScreen may show *Unknown publisher* on first run: choose **More info → Run anyway**.

### Using the app

- **Closing the window** hides it to the tray; sessions keep working. Open it again from the tray icon (double-click or **Open**) or by launching the app again.
- **Quit** (tray menu) stops the companion and every OMP process it started. If sessions are still working it asks first; they are saved as paused. Signing out or shutting Windows down quits without asking.
- **Crash recovery.** If the companion stops unexpectedly (an OMP crash takes it down, say) or stops answering for about two minutes, the app restarts it on the same port with the same token: the window reloads by itself, copied phone links keep working, and **Allow phones on my network** stays on. Screen sharing turns off and needs the tray again. Sessions that were running come back paused; send them a message to continue. A Windows notification says it happened, and the error goes to `%LOCALAPPDATA%\dev.omp.control-room\logs\companion-crashes.log`. After a fourth crash within 10 minutes the app stops retrying, shows the error and closes.
- **Updates.** Installed apps check the latest GitHub release shortly after start and every 6 hours. When there is a newer version, Windows shows a notification and the tray offers **Install update *version*…** (otherwise **Check for updates**). Installing asks first (naming sessions that are still working), downloads the update while the app keeps running, checks its signature, pauses and saves sessions as on Quit, then runs the installer and starts the new version. `npm run desktop` builds don't update themselves.
- **Allow phones on my network** (tray menu, off at every launch) makes the app reachable from your local network. The connection token stays required unless `OMP_WEB_NO_TOKEN=1`: use **Copy phone link** and pick the adapter your phone shares (usually `192.168.x.x`), then open the link on the phone. The token changes every time the app starts, so copy a fresh link after restarting it. With `OMP_WEB_PASSWORD` set, the copied link carries no token and the phone asks for the password instead. Allow the Windows Firewall prompt for **private networks only**.
- **Allow screen sharing and control** (tray menu, off at every launch) lets the dashboard's **Screen** page show this PC's screen and control its mouse and keyboard, from any device that can open the dashboard (so turn on **Allow phones on my network** too for other devices). While a device is viewing, the tray item and tooltip name its address and Windows shows a notification when it connects or leaves; turning the item off disconnects it at once. `OMP_WEB_SCREEN` doesn't apply to the app.
- **Copy phone link** also lists this PC's Tailscale address and MagicDNS name while Tailscale is connected; those links work from anywhere on your tailnet once the firewall allows them, but only while the toggle is on, and it is off after every launch and app update. For Tailscale access that doesn't depend on the toggle, set `OMP_WEB_HOST` to this PC's Tailscale address (see [Away from home with Tailscale](#away-from-home-with-tailscale)).
- **One companion at a time.** The desktop app and `node companion/server.mjs` share `~/.omp-web`, so each refuses to start while the other is running on the same port.
- **`start.bat`** is not the desktop app. It's a double-click launcher for the browser companion: it checks that Bun is installed, runs `npm ci` once if OMP's SDK isn't installed yet, warns when `omp` isn't on PATH (unless `OMP_BIN` is set), then runs `bun companion/server.mjs` and keeps the console open after it stops. **Restart companion** in the dashboard makes it start the companion again in the same console instead (the companion exits with code 75, the code `OMP_WEB_RESTART_EXIT` names); any other exit ends at *The companion stopped.* as before. Unlike the app, it opens the companion to every network adapter (`OMP_WEB_HOST=0.0.0.0`) unless `OMP_WEB_HOST` is already set, including your local network and, if Tailscale runs, your tailnet. Other devices must log in: with the password in `OMP_WEB_PASSWORD` if you set it, otherwise with the random token the console prints on each launch, unless you turned the login off with `OMP_WEB_NO_TOKEN=1`. To keep it on this PC only, set `OMP_WEB_HOST=127.0.0.1` before running it; to accept only your tailnet, see [Tailscale only, no login](#tailscale-only-no-login-optional). It counts as a companion too, so run it or the app, not both.
- `OMP_BIN`, `OMP_WEB_PORT`, `OMP_WEB_DATA_DIR`, `OMP_WEB_NO_TOKEN` and the other variables below still apply. `OMP_WEB_NO_TOKEN=1` drops the token prompt, so once the tray toggle is on **anyone on your network can run commands on this PC**. `npm run desktop` (a debug build) sets it by default; set `OMP_WEB_NO_TOKEN=0` to keep the token there. `OMP_WEB_HOST` only counts when it is this PC's Tailscale address (`100.x.y.z`): the app always starts on `127.0.0.1` and then also listens on that address, from every launch and with your local network still closed; if Tailscale isn't connected yet it retries every 30 seconds. While the tray toggle is on, `0.0.0.0` covers the tailnet too. Any other `OMP_WEB_HOST` is ignored, and only the tray toggle opens the app to your local network.

### Releases

Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml` on a Windows runner: it checks that the tag matches the app version, runs the tests, builds the signed installer and publishes it as a GitHub release together with `latest.json`, the file installed apps poll for updates. To release:

1. Set the same new version in `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and `package.json`, and commit.
2. `git tag vX.Y.Z` and `git push origin vX.Y.Z`.

Updates are signed with the updater key pair. The public key is in `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`); the private key lives outside the repo (`%USERPROFILE%\.tauri\omp-control-room.key`) and in the repository secrets `TAURI_SIGNING_PRIVATE_KEY` (the key file's contents) and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Losing the private key means installed apps can't verify new releases and must be reinstalled by hand. For a local `npm run dist`, set those two variables in the environment first.

## Good to know

- **Don't continue a session in the panel while it's still open in a terminal.** Both would write to the same file.
- **Image attachments:** there is no fixed count. A message's text plus its images must fit the session's remaining context, estimated as about 4 characters per token and (width × height) / 750 tokens per image after a 1568 px / 1.15 MP downscale (at most ~1,530). The composer refuses an image that would overflow and says why; the companion checks again on send, and queued follow-ups sent together go one at a time when their total doesn't fit. Images over 1568 px are scaled down before upload, and one message's images may total up to 45 MB. When the context window is unknown (the *OMP default* model before the session starts, or models not loaded yet), only the upload size limits images.
- **Images in tool output:** when the agent reads an image file (PNG, JPEG, WebP or GIF up to 5 MB), the expanded tool card shows it under the text output; tap it to see it full size. Images load only when their card is open. They show in live sessions, after a reload and in sessions opened from OMP history.
- **Finished turns:** OMP's completed-and-settled result or idle state moves the session to **Ready for review**, even if the separate settled notification is missing. Unrelated command output no longer keeps a finished turn **Working**. Queued continuations stay in the same work interval, and stale or duplicate completion signals cannot finish the next run. Click **Mark done** after reviewing the result. Restart the companion and refresh the browser after updating.
- **Work timing:** counted from the agent's actual start until the session settles with no queued continuation. Stop, terminal failure or companion shutdown also freeze the timer; independent work starts a new interval. Durations persist across reloads and restarts, but past or terminal-only sessions have no invented timing. After updating, finish running work, restart the companion and refresh the browser.
- **Stopping retries:** **Stop** and **Stop retrying** cancel the active turn, including retry backoff and in-flight provider requests. The session returns to Idle, and queued follow-ups stay queued. Restart the companion after updating it, then refresh the browser.
- **Cancelling steers:** **Cancel** removes a steer only while OMP still has it queued. If delivery wins the click, the panel clears the stale controls and shows an informational notice instead of an error; the delivered message stays in the transcript. Restart the companion and refresh the browser after updating.
- **OpenCode Go multi-account limits:** a patched OMP runtime tries another stored account for `429 Output token rate limit exceeded`, including advisor requests. Select it with `OMP_BIN` as shown below; updating the companion alone does not change an installed OMP executable. Generic backend `503` errors remain ordinary retry errors.
- **Subagent reasoning:** Activity cards stay compact so several running subagents fit at once: name, elapsed time and a **Watch →** link on top, then model, description and the live tool/intent line. Expand **Reasoning** to read the current thought; it follows new text until you scroll it and stays open while the panel updates. **Watch** updates the unfinished thought as it streams. Sessions running in a separate terminal only expose saved reasoning. After updating the companion, wait for running work to finish, restart it and refresh the browser.
- **Subagent cost:** the dollar amount on each Activity job covers that subagent's own transcript only, not subagents it started in turn.
- **Subagent reasoning level:** each Activity card, running or finished, shows the model and level, for example `Agent · scout · Claude Opus 5.5 · high · $1.72`. Both come from the subagent's own transcript, so for `auto` it is the level OMP actually picked. The level is left out until the transcript records one.
- **Plugins vs standalone skills:** disabling a plugin does not disable separately installed copies under folders such as `~/.agents/skills`. To disable a skill from every source, add its name (for example, `impeccable`) to `skills.ignoredSkills` in Settings. After plugin changes, use `/reload-plugins` or restart existing sessions. A skill already read remains in that conversation's history; start a new session to remove that context.
- **Worktrees:** tick **Isolated git worktree** when starting a session in a Git repo. You get an `omp-web/<id>` branch off HEAD. Uncommitted changes and dependencies are not copied. Worktrees are never merged or deleted automatically. Isolated sessions show *⎇ worktree* in their sidebar row (hover for the branch) and `⎇ omp-web/<id> (worktree)` in the session header. If no worktree can be made, the session works directly in the folder and its first note says why: the folder is not a Git repository, the repository has no commits yet, or git's own error (a partly created worktree and branch are removed).
- **Not in the panel:** importing from Claude Code or Codex (`--from-claude`, `--from-codex`) needs OMP's terminal picker, and `--profile` sessions live in a separate store the panel does not list. Use the terminal for those, and for the interactive `omp stats` dashboard server and skill publishing.
- **Where data lives:** `~/.omp-web/` holds `workspace.json` (projects with their names, colours and hidden state, sessions, settings, and the sidebar's group order and collapsed groups), each session's panel transcript in `transcripts/<session id>.json`, managed sessions and worktrees. While a session streams, only its own transcript and the small `workspace.json` are rewritten, at most every few seconds; status changes save right away, and quitting, restarting or pausing saves everything. Older companions kept every transcript inside `workspace.json`; the first start of this version moves them out, after which an older companion lists the sessions but fails to send to them (the transcripts stay untouched for this version). Images from tool output are kept in `~/.omp-web/tool-images/`, named by content hash and capped at 256 MB (oldest go first). An image deleted from there still shows while OMP's own blob store (`<agent dir>/blobs`) has it. Sessions started normally also appear in OMP's own store, so `omp --resume` works.
- **Security:** `node companion/server.mjs` listens only on `127.0.0.1` unless you set `OMP_WEB_HOST` (see [Phone or tablet on your network](#phone-or-tablet-on-your-network)). Every API request needs the connection token: the password from `OMP_WEB_PASSWORD` if set, otherwise a random per-launch token. The companion also checks Host and Origin: only `127.0.0.1`, `localhost`, this PC's adapter addresses (when bound to `0.0.0.0`), this PC's Tailscale MagicDNS name (when bound to `0.0.0.0` or the Tailscale address) and names listed in `OMP_WEB_PUBLIC_HOSTS` are accepted, so DNS-rebinding pages are refused. Anyone with the password or token can run shell commands in a session's folder (`!command`, the same as OMP's own `!` prefix), and OMP keeps its usual tools and permissions; with screen sharing allowed, they can also see and control the PC's screen. The screen WebSocket passes the same Host/Origin checks and opens only with a single-use ticket that expires after 30 seconds, is bought with the token and works only from the address that bought it. The companion speaks plain HTTP, so never expose its port to the internet (no router port forwarding); reach it from outside through Tailscale, which encrypts the traffic (see [Away from home with Tailscale](#away-from-home-with-tailscale)). A random token is printed in the companion's console and passed to your browser when it opens the dashboard; on a shared machine, set `OMP_WEB_NO_OPEN=1` and paste the link yourself. A password from `OMP_WEB_PASSWORD` is never printed, put in a link or served in the page (it also overrides `OMP_WEB_NO_TOKEN=1`). Sessions opened in a new tab share the token through the tab's session storage.

### Native plan mode

Click **Enable plan mode** before sending your task, or toggle it with **Alt+Shift+P**. `/plan` and `/plan-review` use OMP's native planning workflow, not a planning-only prompt or automatic approval.

The project stays read-only until you explicitly approve implementation or turn plan mode off. **Review plan** offers **Keep context**, **Fresh context**, **Compact context**, **Save and quit**, an optional execution model, and **Request refinement** with required feedback. Closing the review leaves it unapproved. Stale proposals must be reviewed again.

- **/plan [on|off|parallel|iterative|prompt]**: with no argument it cycles on → paused → off, as in the terminal UI. `/plan <prompt>` enters plan mode and sends the prompt as the first planning turn. Leaving plan mode while a draft plan exists asks **Exit plan mode?** first.
- **/plan-review**: reopens the review of the latest plan while plan mode is on, for example after pressing Stop on a review. Stopping during **Compact context** keeps the plan approved without running it; your next message continues with the plan.
- **Save and quit** writes the plan to a project file (default `<TITLE>_PLAN.md` in the session's folder, or the **Save to** path), leaves plan mode and starts a new session, as the terminal UI does.

An OMP SDK that ships its own plan-mode host (`modes/rpc/rpc-plan-mode.ts`) is used as is. Released SDKs such as 18.12.5 and 18.12.6 don't, so the companion hosts plan mode itself (`companion/plan-host.mjs`) on the pieces those SDKs ship, with the terminal UI's prompts, refusals and approval flow. With `plan.enabled` off, `/plan` is not listed and plan requests are refused. On released SDKs a background turn (an IRC wake-up or a queued hidden message) that starts during a pending review is stopped before it reaches the model, but its input still enters the context; holding it back needs OMP's `reviewPending` checks in `AgentSession`.

Sessions run the OMP SDK in the companion's own process: by default the npm package `@oh-my-pi/pi-coding-agent` installed with the companion, or the newer release installed under `<data dir>/omp-sdk/` to match the `omp` CLI (see *OMP stays current*); if that copy fails to load, sessions fall back to the bundled one. To run OMP changes that are not released yet, set `OMP_BIN` before starting the app or `node companion/server.mjs` to a prepared checkout's `packages\coding-agent\src\cli.ts` (the checkout needs its dependencies, generated tool views and native bindings); sessions then load that checkout's SDK, and the CLI features run its `cli.ts` through Bun. An `OMP_BIN` naming a compiled executable changes the CLI features and the CLI whose version the SDK follows. Restart the companion after changing the runtime.

### Native goal mode

Type `/goal` to open the objective prompt or manage the current goal. `/goal <objective>` starts work directly; `/goal set <objective>` replaces an active objective. `/goal show`, `/goal pause`, `/goal resume`, `/goal budget <N|off>` and `/goal drop` use OMP's native goal runtime. Dropping a goal requires confirmation in the browser.

An OMP SDK that ships its own `/goal` host (`modes/rpc/rpc-goal-slash.ts`) is used as is. Released SDKs such as 18.12.5 don't, so the companion hosts `/goal` itself (`companion/goal-host.mjs`) on the goal controller and goal runtime those SDKs ship, with the same commands, dialogs and messages. `goal.enabled` must be on; otherwise `/goal` is not listed and is rejected rather than sent to the model. A goal can't start while plan mode is active or paused, or while vibe mode is on. Command discovery starts an idle session's runner, but restored goals remain paused until you explicitly resume them.

Automatic continuation follows `goal.continuationModes`'s `interactive` profile. It stops on completion, pause/drop, exhausted budget, blocked work, errors, or no progress.

### OMP's terminal-UI commands

The companion runs the slash commands OMP ships only for its terminal UI through its own hosts (`companion/command-hosts.mjs`), on OMP's own controllers wherever OMP exposes them. Their panels appear as widgets under the composer, their pickers and prompts as dashboard dialogs, and **Stop** stands in for Esc. A terminal-UI command the companion doesn't run (for example `/new`, `/resume`, `/settings` or `/hotkeys`) is refused with a pointer to the dashboard's equivalent instead of being sent to the model as text. While you type `/command `, the composer completes its subcommands.

- **/fork**: copies this session into a new session file and continues there with the same context.
- **/clear**: drops the conversation from the model's context and keeps going in the same session; the session file keeps the earlier messages and the transcript shows where the context was reset. Refused while OMP is working.
- **/logout [provider]**: removes a stored login, asking which provider and account when there are several.
- **/loop [count|duration] [--while|--until '<cmd>'] [prompt]**: the prompt (or the next one you send) is sent again after every turn until the count or duration runs out; `/loop N` gives N repeats after the first turn. `--while`/`--until` runs a shell command before each repeat, and its exit status decides whether the loop continues. Stop pauses the loop and your next prompt resumes it; `/loop` again, `/loop off`, the bar's **Stop loop** button or switching sessions turns it off. OMP's `loop.mode` setting is honoured (`compact` compacts before each repeat, `reset` starts each repeat in a fresh session), and `loop.conditionTimeoutMs` limits the condition command. While a loop runs, goal mode doesn't start its own continuation turns; turning the loop off with `/loop` or `/loop off` lets the goal continue.
- **/tan <work>**: runs a full agent in the background on a copy of this conversation without interrupting it. A *Tangent dispatched* line marks the start; the result arrives later as a background job. Needs a saved session.
- **/seance [session id|path] [--model selector]**: asks the seance agent about a saved session without resuming it. With no argument, pick from this folder's sessions, or choose **All projects…** to see every project's. Pick the saved model or a one-off model; the answer arrives as a background result.
- **/todo edit**: opens the todo list as Markdown in an editor dialog (`# Phase`, `- [ ]` / `- [/]` / `- [x]` / `- [-]` / `- [!]` tasks). Saving replaces the list and tells the agent what changed; Cancel leaves it as it was. Other `/todo` subcommands work as in OMP.
- **/omfg <complaint>**: the model writes a rule from your complaint and checks it against this conversation in a live panel. Save it to this project, globally, or amend it with feedback; the saved rule is active immediately. The finished panel is posted to the chat. Like `/cleanse`, it runs in the background with its own **■ Stop /omfg** button in the composer; the turn's ■ doesn't cancel it.
- **/cleanse [request] [--all] [--tests] [-n agents] [-m model]**: finds the project's checkers in the session's folder (or asks what to fix), runs them, sends parallel fix agents and re-checks. A live board appears under the composer and the summary is posted to the chat. The fix agents use the companion's OMP settings rather than the session folder's, because OMP's cleanse runtime loads settings process-wide.
- **/guided-goal [rough objective]**: the agent interviews you in the chat (success criteria, verification, attempt cap, scope, stop conditions), then starts goal mode with the objective you agreed on. Stop abandons the interview without creating a goal. Hidden when `goal.enabled` is off.
- **/vibe [prompt]**: toggles vibe mode: the agent becomes a director with a read-only toolset plus `vibe_*` tools that spawn and steer persistent worker sessions. A prompt after `/vibe` starts the first vibe turn. `/vibe` again exits, which stops the workers and restores the normal tools. Not available while plan or goal mode is on; `/new` and `/fork` wait until you exit.
- **/pause**: pauses every agent in the companion (all sessions, their subagents and advisors; OMP has a single process-wide pause gate). Each stops at its next step and calls already running finish. Choose **Resume all agents** in the dialog, or press Stop or close that session, to continue.
- **/live [start|stop|mute|unmute]**: starts a Codex realtime voice call using the microphone and speakers of the computer running the companion (needs an OpenAI Codex login). What you ask for runs as normal turns, transcripts appear in the chat and a widget shows the call's state. `/live` again, `/live stop`, Stop, or changing or closing the session ends the call.
- **/collab [view|status|list|stop] [relay]**: shares this session live through OMP's collab relay with the same links as the terminal UI (terminal `omp join "…"` and browser). The link and guest count show in the session's status line, with a QR code under the composer. Questions the agent asks (choices, text editors, the ask tool) also go to guests with write access; the first answer wins. `view` shares a read-only link; `stop` or `/leave` ends sharing. Set `collab.relayUrl` in OMP settings, or pass a relay. With `collab.autoStart` set to `view` or `control`, every session is shared as it opens.
- **/join <link>**: joins someone else's shared session. You see the host's transcript and live activity, including the host's and other guests' prompts as they are sent (guests' with their names). Your messages go to the host's agent, Stop interrupts it, and the Activity panel can stop or steer the host's running subagents. Local commands, `/goal`, `/plan`, shell, compaction, model changes and session changes stay off until you leave.
- **/leave**: leaves a joined session and returns to your own, or stops sharing if you are the host.

Extension commands that draw their own terminal UI (`ctx.ui.custom`) open as a terminal panel in the session: it shows the component's output with its colours, takes keys while focused, offers on-screen keys for touch devices, and follows the panel's size in your browser. Bash tool calls with `pty: true` run in the same panel, so interactive programs work; **Close panel**, Stop or closing the session ends them. A companion started from a shell where `PI_NO_PTY=1` is set keeps PTY off, as OMP does.

Other session controls: the reasoning-level menu lists the levels the running model actually supports and refuses others; the session's ⋯ menu has OMP's **Slow mode** switch (shown only for models that support it; not replayed when the session restarts, because OMP stores it with the model) and **Cache warming** (off, while streaming, or idle). Provider logins that ask for input (an API key, or a masked secret) ask in a dashboard dialog; secrets use a password field and are never stored by the companion.

| `OMP_BIN` | `omp` | OMP CLI for updates, usage, enhance and the Tools page, and the version the session SDK follows; a prepared checkout's `cli.ts` also makes sessions use that checkout's SDK |
| `OMP_WEB_PORT` | `4545` | Companion port |
| `OMP_WEB_HOST` | `127.0.0.1` | Bind address; `0.0.0.0` opens it to your local network (see below), a single address such as this PC's Tailscale `100.x.y.z` accepts only connections to that address. The desktop app only honors this PC's Tailscale address, as a listener beside `127.0.0.1` |
| `OMP_WEB_PASSWORD` | unset | Password every device must enter (replaces the random per-launch token). Printable ASCII, no leading or trailing spaces. Never printed or served in the page; overrides `OMP_WEB_NO_TOKEN` |
| `OMP_WEB_PUBLIC_HOSTS` | none | Comma-separated host names accepted in the Host and Origin headers, matched exactly, e.g. a reverse-proxy name or a Tailscale short name `my-pc` (this PC's full MagicDNS name is accepted without it when bound to `0.0.0.0` or the Tailscale address) |
| `OMP_WEB_NO_TOKEN` | unset | `1` serves the token inside the page, so no device is asked for it. Ignored when `OMP_WEB_PASSWORD` is set |
| `OMP_WEB_SCREEN` | unset | `1` allows the **Screen** page to show and control this PC (Windows only). Ignored by the desktop app, which has its own tray toggle |
| `OMP_WEB_DATA_DIR` | `~/.omp-web` | Panel state, sessions and worktrees |
| `OMP_SESSIONS_DIR` | `<agent dir>/sessions` | OMP's native session store |
| `PI_CODING_AGENT_DIR` | `~/.omp/agent` | OMP agent directory (`config.yml`, `WATCHDOG.yml`) |
| `OMP_ALLOWED_ORIGINS` | none | Extra browser origins allowed to connect (see below) |
| `OMP_WEB_NO_OPEN` | unset | Don't open the browser on start |
| `OMP_WEB_NO_UPDATE` | unset | `1` skips the `omp update` run and the matching SDK install on start |

### Hosted dashboard (optional)

The local dashboard is the most reliable option. To use the hosted one instead, allow its origin, then connect to `http://127.0.0.1:4545` with the printed token:

```sh
OMP_ALLOWED_ORIGINS=https://omp-control-room.ataberk-oztrk3.chatgpt.site node companion/server.mjs
```

Your browser may block HTTPS-to-localhost requests. If it does, use the local dashboard.

### Phone or tablet on your network

In the desktop app, use the tray's **Allow phones on my network** and **Copy phone link** (see [Desktop app](#desktop-app-windows)); the token stays required.

Without the app, start the companion on every network adapter with a password (`start.bat` binds to `0.0.0.0` already):

```bat
set OMP_WEB_HOST=0.0.0.0
set OMP_WEB_PASSWORD=choose-a-long-password
node companion/server.mjs
```

The console prints a `LAN:` address per adapter (usually the `192.168.x.x` one); open it on a phone on the same Wi-Fi and enter the password. Without `OMP_WEB_PASSWORD`, the `LAN:` links carry a random token that changes every launch. Allow Bun through Windows Firewall for private networks when prompted. Adding `set OMP_WEB_NO_TOKEN=1` (without a password) skips the login, but then **anyone on that network can open the address and run commands on this PC**; use it only on networks you trust.

To keep the password across launches, store it in your user environment once (`setx OMP_WEB_PASSWORD "…"` in a new console, or *Edit environment variables for your account*) instead of in `start.bat` or any file in this repo.

### Away from home with Tailscale

Use [Tailscale](https://tailscale.com) to reach the companion over mobile data or another Wi-Fi. It connects your devices over an encrypted WireGuard network (a *tailnet*), so nothing is opened on your router and the plain-HTTP traffic never crosses the internet unencrypted. Don't forward the companion port on your router instead.

1. On this PC: install Tailscale (`winget install --id Tailscale.Tailscale -e`), sign in, and note its addresses with `tailscale ip -4` (a `100.x.y.z` address) and `tailscale status --json` (`Self.DNSName`, e.g. `my-pc.tailnet-1234.ts.net`).
2. On the phone: install the Tailscale app and sign in to the **same** tailnet (same account or invited user). Leave the VPN toggle on.
3. Start the companion with `OMP_WEB_HOST=0.0.0.0` and `OMP_WEB_PASSWORD` set (`start.bat` does the first). The `100.x.y.z` address is one of this PC's adapters and the companion asks Tailscale for this PC's MagicDNS name, so both are accepted without further settings; the console prints a `Tailscale: http://my-pc.tailnet-1234.ts.net:4545/` line. For the desktop app, store this PC's address once with `setx OMP_WEB_HOST 100.x.y.z` and restart the app (**Quit** from the tray, then start it): it then listens on the tailnet from every launch while your local network stays closed. Turning on **Allow phones on my network** and picking a *Tailscale* entry in **Copy phone link** works too, but only until the app restarts or updates.
4. Allow the port from the tailnet only, in an administrator console: `netsh advfirewall firewall add rule name="OMP companion (Tailscale)" dir=in action=allow protocol=TCP localport=4545 remoteip=100.64.0.0/10`. The rule is per port, so it covers the desktop app too.
5. On the phone open `http://100.x.y.z:4545/` (or `http://my-pc.tailnet-1234.ts.net:4545/`) and enter the password. The **Screen** page works over Tailscale as well once screen sharing is allowed on the PC; on mobile data, *Fast* quality keeps it responsive.

#### Tailscale only, no login (optional)

If you'd rather have the dashboard open straight away on your tailnet devices, bind the companion to this PC's Tailscale address and turn the login off. Store the settings once in your user environment, in a normal console (`OMP_WEB_PASSWORD` must go, because it overrides `OMP_WEB_NO_TOKEN`):

```bat
reg delete HKCU\Environment /v OMP_WEB_PASSWORD /f
setx OMP_WEB_NO_TOKEN 1
setx OMP_WEB_HOST 100.x.y.z
```

Close the companion's console, then start `start.bat` from Explorer or a **new** console (open consoles keep the old variables). The console prints `Open: http://100.x.y.z:4545/` and `No token required: anyone who can reach this port has full control.`

- Only the Tailscale address answers: `http://127.0.0.1:4545` on the PC itself stops working, so open `http://100.x.y.z:4545/` there too. The MagicDNS name works as well (the console prints it).
- Tailscale must be connected on the PC when the companion starts; otherwise it stops with *could not start*.
- Because the companion listens on the Tailscale address only, your home LAN can't reach it, even when Windows has a broad allow rule for Bun on private networks.
- The desktop app reads the same `OMP_WEB_HOST`, but keeps `127.0.0.1` for its own window and adds the Tailscale address beside it; it does not stop when Tailscale isn't connected yet, it retries every 30 seconds. Restart the app after `setx`.
- **Anyone on your tailnet can open the address and run commands on this PC**, with no password, and with `OMP_WEB_SCREEN=1` also see and control its screen. Remove devices you don't use from the tailnet and don't share this PC with other users.
- `OMP_WEB_NO_TOKEN=1` now applies to the desktop app too: its tailnet listener needs no login either, and its **Allow phones on my network** toggle would open it to your local network without a token.

To go back, run `reg delete HKCU\Environment /v OMP_WEB_NO_TOKEN /f`, `reg delete HKCU\Environment /v OMP_WEB_HOST /f` and `setx OMP_WEB_PASSWORD "…"`, then restart the companion from a new console.

## Development

```sh
node --test "tests/*.test.mjs"
```

`companion/` is the server; it runs on Bun (`node companion/server.mjs` starts it under Bun) and stays importable by Node for the tests. `local-dist/` is the prebuilt dashboard, which you edit directly because the frontend source isn't in this repo. `src-tauri/` is the Tauri shell for the Windows app; it starts the bundled Bun with `desktop/host.mjs`, which runs the companion and talks to the shell over stdin/stdout. Sessions run in-process through OMP's SDK (`companion/omp.mjs`): each one is an OMP `AgentSession` built with OMP's own CLI option builders, so launch flags, resume and continue behave as in `omp`, and hosted with OMP's in-process controllers for dialogs, side questions, subagents, prompt results, settling and goals (plus plan mode and OMP's own `/goal` host when the SDK ships them; otherwise `companion/plan-host.mjs` and `companion/goal-host.mjs` host them). Terminal-UI commands run through the hosts listed in `companion/command-hosts.mjs`, whose header documents the host contract; `companion/custom-ui.mjs` bridges `ctx.ui.custom` components to the dashboard's terminal panel. `companion/omp-sdk.mjs` chooses the SDK copy sessions load and installs the release matching the `omp` CLI. Error messages that mention RPC refer to the plan/goal hosts, which OMP ships under `modes/rpc/`.

**Not supported:** attaching to already-running terminal sessions and automatic Git merges.
